4. PNG DECODING PROCESS
=======================

    Input: "C:\sequences\frame_001.png"
            |
            v
    std::ifstream load full file into memory
            |
            v
    stbi_load_from_memory(buffer, size, ?, ?, ?, 4)
            |   Force RGBA output (4 channels)
            |
            v
    unsigned char* imageData (raw RGBA, straight alpha)
            |
            v
    premultiplyAlpha(imageData, width, height)
            |
            +-- For each pixel:
            |   R_out = (R * A) / 255
            |   G_out = (G * A) / 255
            |   B_out = (B * A) / 255
            |   A_out = A (unchanged)
            |
            v
    Copy to DecodedFrame.data (std::vector<uint8_t>)
            |
            v
    stbi_image_free(imageData)
            |
            v
    Output: DecodedFrame (RGBA8 premultiplied)


5. MEMORY LAYOUT (Example: 1920x1080)
=====================================

    INPUT: PNG file on disk
    ---------------------
    Compressed PNG data: variable size (depends on compression)


    DURING DECODING: std::vector<uint8_t> buffer
    ---------
    Full PNG file: 500KB - 5MB


    DECODED OUTPUT: uint8_t* imageData (stb_image)
    ------------------
    1920 * 1080 * 4 bytes = 8.3 MB (RGBA8)


    FINAL OUTPUT: DecodedFrame.data
    ----------------
    1920 * 1080 * 4 bytes = 8.3 MB (RGBA8 premultiplied)

    Memory freed:
    - std::ifstream buffer (automatic cleanup)
    - stb_image imageData (stbi_image_free)
    - Temporary allocations released


6. ECS INTEGRATION
==================

    Component: Clip
    ===============
    struct Clip {
        std::string filepath;  // "C:\sequences\frame_001.png"
        FrameNumber startFrame;
        FrameNumber duration;
    }


    DecodeSystem (owns decoders)
    ===============
    class DecodeSystem {
        std::unordered_map<EntityID, std::unique_ptr<Decoder>> decoders;

        for entity in registry.view<Clip, FrameBuffer>:
            decoder = createDecoder(detectMediaType(clip.filepath))
            decoder.open(clip.filepath)

            decodedFrame = decoder.decodeFrame(targetFrame)
            frameBuffer.push(decodedFrame)
    }


    Component: FrameBuffer (ring buffer)
    ==============
    class FrameBuffer {
        std::vector<DecodedFrame> frames;  // 32 frames
        std::atomic<uint32_t> writeIndex;
        std::atomic<uint32_t> readIndex;

        bool push(DecodedFrame&& frame)  // from decoder
        bool pop(DecodedFrame& frame)    // to compositor
    }


    CompositorSystem
    ===============
    for entity in registry.view<VideoTexture, FrameBuffer>:
        frame = frameBuffer.pop()
        uploadTexture(frame, videoTexture)  // GPU upload


    RenderSystem
    ============
    for entity in registry.view<VideoTexture, Transform>:
        renderTexture(videoTexture, transform)

===============

10. PERFORMANCE CHARACTERISTICS
================================

    Operation            Time        Memory      Notes
    ---------            ----        ------      -----

    scanDirectory()      1-5 ms      Minimal     One-time, cached

    loadPNG()            5-15 ms     16-20 MB    File I/O + decode
                                                 Depends on PNG size
                                                 and compression

    premultiplyAlpha()   0.5-2 ms    In-place    Simple pixel math

    seek()               <1 ms       None        Just updates state

    Total frame decode   5-15 ms     8.3 MB      For 1920x1080

    Per-frame memory     8.3 MB      Peak 16 MB  During decode


11. FILENAME CONVENTIONS
=======================

    SUPPORTED PATTERNS:

    frame_001.png       ✓ Alphabetic sort works
    frame_002.png       ✓
    frame_010.png       ✓ (zero-padded for correct sort)

    image_001.png       ✓
    seq_0001.png        ✓

    AVOID THESE:

    frame_1.png         ✗ Alphabetic sort fails:
    frame_2.png         ✗   frame_1, frame_10, frame_2 (WRONG ORDER)
    frame_10.png        ✗ Use zero-padding: frame_01, frame_02, ..., frame_10
